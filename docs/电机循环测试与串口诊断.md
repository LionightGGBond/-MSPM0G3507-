# 电机循环测试与Type-C串口诊断

当前默认已恢复循迹（`ROBOT_MOTOR_TEST_MODE=0`）。本页的转2秒/停2秒和s/r暂停继续操作，需要先将该宏改为1、重新编译下载。测试先架空车轮；仍使用原来的唯一main、10ms控制中断、OLED和IMU，无需复制第二份main。串口中文诊断在循迹模式下仍有效，IMU离线不阻止循迹。

## 运行和参数

初始化结束→等待2秒→两轮固定30% PWM转动2秒→两轮短路刹车2秒→重复。固定PWM不代表固定转速；方向按MOTOR_SIGN修正。测试不因丢线、交叉线、编码器无计数或IMU离线而停车，也没有原循迹的100秒结束限制。不能用此模式测试堵转；它故意不启用编码器缺失停车，以便检查反馈接线。

参数集中在根目录 `robot_config.h`：

```c
#define ROBOT_MOTOR_TEST_MODE 1  /* 0恢复原循迹和速度PID */
#define ROBOT_TEST_ON_MS      2000U
#define ROBOT_TEST_OFF_MS     2000U
#define ROBOT_TEST_LEFT_PWM   30 /* -100..100整数；0停止该轮，负值反转 */
#define ROBOT_TEST_RIGHT_PWM  30
#define ROBOT_DEBUG_REPORT_MS 500U
```

示例：LEFT=30、RIGHT=0单独测试左轮；LEFT=0、RIGHT=30单独测试右轮。PWM过低可能无法克服静摩擦，须结合电机供电和空载情况调整。

四个方向输入的电平单独集中在 `robot_config.h` 中：

```c
#define ROBOT_TB6612_AIN1_FORWARD_LEVEL 0U /* PA15，右轮 */
#define ROBOT_TB6612_AIN2_FORWARD_LEVEL 1U /* PA16，右轮 */
#define ROBOT_TB6612_BIN1_FORWARD_LEVEL 0U /* PB0，左轮 */
#define ROBOT_TB6612_BIN2_FORWARD_LEVEL 1U /* PB1，左轮 */
```

0表示低，1表示高。以上定义驱动正向时的电平，同通道须一高一低；反向时交换该对电平，停车时强制11短路制动。当前两轮测试PWM均为+30，MOTOR_SIGN均为+1，所以：

| 阶段 | AIN1（PA15） | AIN2（PA16） | BIN1（PB0） | BIN2（PB1） |
| --- | --- | --- | --- | --- |
| 初始化、等待、测试停车、手动暂停、故障停车 | 高 | 高 | 高 | 高 |
| 测试转动2秒 | 低 | 高 | 低 | 高 |
| 两轮负PWM反转（先经过一拍刹车） | 高 | 低 | 高 | 低 |

因此电平随2秒转停阶段切换，并非一直固定。高电平预期接近MCU供电3.3V，低电平接近0V；这描述代码输出，实际电压用万用表或逻辑分析仪测量。

硬件写入统一在 `Bsp/tb6612.c` 的 `SetInputLevels()`，正常使用修改上面的配置即可。不要在主循环另加方向GPIO写入，否则下一次10ms控制中断会覆盖。中文“底盘”日志新增 `方向输出(AIN1/2=01,BIN1/2=01)`，两位从左到右依次是IN1、IN2；停车应为11/11。这读取GPIO输出锁存寄存器，不能代替引脚电压实测。

定时器配置错误、控制周期超出8..12ms、主循环超过250ms未响应仍锁存停车。故障不能用串口r解除，修正后复位。主循环超时保护依赖控制中断仍能执行；程序没有独立硬件看门狗。STBY仍固定3.3V。

## SysConfig界面配置

按原清单保留电机、编码器、GPIO、I2C配置；测试模式仍采样编码器。用户自行配置 `empty.syscfg`，本次没有自动覆盖它。

先修正现有PWM：在 **TIMER - PWM → MOTOR_PWM → Basic Configuration** 将 **PWM Period Count设为1600**；PWM Channel 0和1的 **Counter Compare Value均为1599**，Desired Duty Cycle=0%、Initial Value=Low、Channel Update Mode=Zero Event。生成LOAD应为1599。Period填1599会生成1598，屏幕PWM CONFIG并保持刹车；不要去掉校验绕过问题。

左侧Software中在 **UART** 旁点“+”，按下表配置：

| 界面位置/字段 | 配置值 |
| --- | --- |
| Name | `DEBUG_UART`，名称须完全一致 |
| UART Profiles | Custom；不要选Internal Loopback模板 |
| Basic Configuration → Clock Configuration | BUSCLK=32MHz，Clock Divider=1 |
| Target Baud Rate | 115200 |
| UART Mode | Normal |
| Communication Direction | TX and RX |
| Hardware Flow Control | None |
| Parity | None |
| Word Length / Stop Bits | 8 bits / One |
| Enable FIFO | 勾选；TX/RX FIFO阈值保持默认 |
| Enable Internal Loopback | 不勾选 |
| Enable UART（若显示） | 勾选 |
| Interrupts / DMA / Event | 均不启用；代码轮询FIFO，不开UART NVIC |
| PinMux → UART Peripheral | UART0 |
| PinMux → TX Pin | PA10 |
| PinMux → RX Pin | PA11 |

保存后检查生成头文件含 `#define DEBUG_UART_INST UART0`。CCS刷新工程（新文件 `Bsp/debug_uart.c` 应出现在工程中），Build，再下载。没有添加UART时其代码自动禁用，OLED显示UART:OFF，电机测试仍可工作；添加成功显示UART:ON。

板载CH340E已经连接UART0 PA10/PA11，连接开发板的数据Type-C接口即可，无需另接USB转串口。接口依据：[立创天猛星CCS串口手册](https://wiki.lckfb.com/zh-hans/tmx-mspm0g3507/ccs-beginner/uart.html)。本次占用原给K230预留的UART0，**不要同时连接K230 TX和CH340 TX到PA11**；K230后续可另选串口并重新核对引脚。

## 电脑操作

串口工具打开CH340对应COM口：**115200、8数据位、无校验、1停止位、无流控，接收文本编码UTF-8**，关闭十六进制发送。串口日志和命令提示已改为中文；若乱码，切换接收编码为UTF-8，不能按纯ASCII或GBK解码。发送命令仍为下面的单个ASCII字符。使用可传数据的Type-C线；设备管理器无CH340端口时检查数据线和驱动。Type-C用于MCU供电与通信，TB6612的VM仍须按电机规格单独供电并共地。

| 发送ASCII字符 | 行为 |
| --- | --- |
| `?` 或 `h` | 输出帮助和一次诊断；其余时间每500ms自动输出 |
| `s` | 请求暂停，下一次10ms控制中断进入TEST PAUSE，两轮刹车并保持 |
| `r` | 从暂停恢复，重新开始完整的转2秒/停2秒循环；不清除故障锁存 |
| `i` | 仅在TEST PAUSE、结束或锁存故障状态重新初始化IMU；随后静止标定 |

每个命令只需一个字符，可带回车。s/r仅测试模式有效。先发送s，确认下一条中文日志状态为“测试暂停”（OLED显示TEST PAUSE）后，再发送i。静止观察至少1秒，满足标定条件后“标定”应达到100/100。不要在连续转动阶段判断零偏标定进度。

## 日志解释与排查

每次输出五行中文：“系统”“底盘”“IMU”“IMU探测”“IMU数据”。汉字按UTF-8编码，单行格式化缓冲448字节，发送队列2KB；分行保留容量余量，非阻塞装入TX FIFO。队列满时整行丢弃并累计“发送丢行”，不拖住电机控制。请勿连续粘贴大量命令；RX使用轮询，长设备初始化期间可能溢出，“接收错误”可帮助发现。以下数值仅为格式节选，不是实测，另有一行IMU探测诊断：

```text
系统 时间=2500ms 模式=电机测试 状态=测试转动 心跳=2 配置错误位=0x0 PWM装载值=1599 控制定时器装载值=9999 中断次数=250 控制间隔=10ms
底盘 循迹位=0x04 左轮(PWM=30%,计数=12) 右轮(PWM=30%,计数=12) 右编码器非法跳变=0 发送丢行=0 接收错误=0
IMU 地址=0x68 芯片标识=0x68 在线=是 故障=正常 总线=成功(0) 累计错误=0 标定=100/100 标定完成=是 姿态有效=是 末次采样=2500ms SCL=1 SDA=1
IMU数据 加速度原始=0,0,16384 陀螺仪原始=0,0,0 温度原始=0 角度单位=0.1度 俯仰=0 横滚=0 偏航=0
```

| 字段/现象 | 含义和检查方向 |
| --- | --- |
| 配置错误位 | 定时器错误位：0x1 PWM时钟、0x2 PWM LOAD、0x4控制时钟、0x8控制LOAD；可叠加 |
| PWM装载值 / 控制定时器装载值 | 应为1599 / 9999；前者1598表示PWM Period Count少了1 |
| 中断次数 / 控制间隔 | 中断累计次数/相邻中断毫秒差，正常间隔10ms；次数不增长检查Zero event和启动 |
| PWM | 有符号PWM命令百分比；测试停车/测试暂停应为0 |
| 计数 | 最近一个10ms窗口四倍频计数；向前应为正。PWM有输出但计数0时区分轮不转与编码器缺失 |
| 方向输出 | GPIO输出锁存值，AIN1/2和BIN1/2分别按IN1、IN2排列；当前正向为01/01，停车为11/11 |
| 右编码器非法跳变 | 右轮非法AB跳变累计数，增加时检查接线、干扰、漏边沿 |
| 地址 / 芯片标识 | 当前地址与WHO_AM_I寄存器；真MPU6050的标识应为0x68，即便地址是0x69 |
| 在线 / 末次采样 | 最近读取是否成功及最后成功样本时间；离线时原始值可能是旧值，不能当新数据 |
| 总线 | 0成功、1超时、2硬件通信错误、3参数错误，同时给出中文说明；2不能直接认定只有NACK一种原因 |
| 故障=器件未应答 / 通信超时 | 默认先探测0x68、无应答再试0x69；检查模块电源、共地、PA1=SCL/PA0=SDA、上拉和AD0 |
| 故障=芯片标识不符 | 总线上有回应但不是预期WHO；核对实际芯片型号，不要只改ID绕过 |
| 累计错误 | 累计初始化/读取错误数，重试保留 |
| 标定 / 标定完成 / 姿态有效 | 连续稳定标定样本数/陀螺零偏标定是否完成/姿态有效标志；偏航只有标定完成后才有效，且会漂移 |
| 加速度原始 / 陀螺仪原始 | 三轴原始寄存器值；当前量程分别为16384计数/g、65.5计数/(°/s) |
| 温度原始 | 温度原始值，温度°C=原始值/340+36.53 |
| 俯仰 / 横滚 / 偏航 | Pitch/Roll/Yaw的十分之一度整数，例如123为12.3度；须同时看在线、姿态有效、标定完成 |
| SCL / SDA | 从I2C控制器MBMON读取的总线监视值；空闲通常均高，持续低时用万用表/逻辑分析仪检查短路、上拉、供电等。此前版本用GPIO DIN读取已复用引脚，不能根据旧版0/0直接认定物理总线被拉低 |
| IMU探测 | 分别记录0x68和0x69是否尝试、返回码、WHO标识、失败阶段和恢复前MSR。未尝试时结果0不表示成功，应先看“已试” |
| 地址未应答 / 数据未应答 / 仲裁丢失 | 最近事务MSR的ADRACK/DATACK/ARBLST位，1表示该错误发生；0不代表整笔事务必然成功，还须看结果码和阶段 |

屏幕仍保留Pitch、Roll、Yaw、IMU状态和心跳；测试模式底部改为两轮PWM/ENC。循迹五路原始位在中文“底盘”日志中输出。OLED使用原ASCII字库，串口中文不需要给OLED增加中文字库。

缺失设备在WAIT、手动暂停和故障停车时允许每秒重试；测试的自动2秒停车段不重新初始化，以免跨起转边界重置IMU。运行中已初始化的IMU读失败后继续有界重读，错误计数不清零。IMU姿态仍仅用于显示和诊断，不参与本测试控制。

## 验证范围

独立验证脚本支持 `--line-mode` 完整编译原循迹模式、`--without-uart` 验证未配置UART的兼容分支。引脚求解、严格编译、链接及向量表检查通过不代表完成实机验证。仍需实机确认电机方向、驱动电源、转停时长、编码器和IMU通信。
