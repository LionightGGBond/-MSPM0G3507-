# 工程结构与调参指南

本次整理保留当前已运行的接线、PID、速度、循迹策略和控制周期。入口仍叫 `empty.c`，便于继续使用现有 CCS 工程；它承担 STM32 工程中 `main.c` 的职责。

## 先从 empty.c 阅读

`main()` 先调用同文件的 `System_Init()`，再进入真正的 `while (1)`。初始化顺序与前台任务直接在入口文件中展开，便于阅读和扩展。

初始化顺序：

1. `Board_Init()`：SysConfig 外设、GPIO、1ms SysTick、中断优先级。
2. `TB6612_Init()`、`Encoder_Init()`：先建立制动状态，再启动 PWM 和编码器。
3. `Oled_Init()`、`Mpu6050_Init()`：记录就绪状态，设备离线不阻止底盘运行。
4. 初始化心跳、任务时间戳、控制状态机和双轮 PID。
5. 核对定时器参数，通过后开放并启动 10ms 控制定时器；失败则保持制动。

主循环按顺序执行六组任务：串口收发与存活标记、心跳及 LED/蜂鸣器、IMU 采样、停车时设备重试、中文诊断输出、OLED 绘制与逐页发送。顶部设置各任务周期。

同文件的 `CONTROL_TIMER_INST_IRQHandler()` 是固定周期控制入口：

```mermaid
flowchart LR
    A[10ms 定时中断] --> B[编码器增量采样]
    B --> C[读取五路循迹]
    C --> D[状态检查与差速目标]
    D --> E[左右轮速度 PID]
    E --> F[TB6612 输出]
```

编码器 GPIO 中断留在 `Bsp/encoder.c`，SysTick 中断留在 `Bsp/board.c`。这些属于对应硬件模块，入口只保留一份定义。OLED、IMU、串口报告在主循环运行。

## 文件职责

| 文件 | 职责与边界 |
| --- | --- |
| `empty.c` | 统一初始化、主循环、控制中断、共享数据快照、串口命令分发；后续功能在此接入任务 |
| `Motion/controller.c` | 控制状态机、时序检查、无效线型策略、PID调用；计算输出但不写电机引脚 |
| `Motion/line_follow.c` | 五路标准线型映射为左右目标；无效线型交给控制状态机处理 |
| `Motion/pid.c` | 双轮离散速度PID；不操作GPIO、不安排任务 |
| `Motion/quadrature.c` | 右轮AB状态变化解码；不处理显示和运动策略 |
| `Bsp/board.c` | SysConfig启动、GPIO电平转换、时基、临界区、定时器核对 |
| `Bsp/encoder.c` | 左轮硬件QEI、右轮GPIO双边沿、周期计数采样 |
| `Bsp/tb6612.c` | AIN/BIN电平、方向切换制动、死区、PWM输出 |
| `Bsp/i2c_bus.c` | 硬件I2C事务、超时与总线诊断 |
| `Bsp/debug_uart.c` | UART收发、非阻塞发送队列；不决定底盘状态 |
| `Devices/oled.c` | SSD1306初始化、帧缓存、字符绘制、I2C逐页发送 |
| `Devices/mpu6050.c` | 器件探测、采样、静止标定、互补滤波与IMU诊断 |
| `App/robot_app.c` | 根据只读快照生成OLED页面和中文日志；任务节拍由入口安排 |
| `robot_config.h` | 固定控制周期及测试/停车功能开关 |

## 参数在哪里修改

所有可调参数放在所属 `.c` 文件顶部的“本模块参数”或相应参数区。头文件声明接口和数据类型，跨模块需要的参数通过 `extern const` 只读访问，避免多份数值不一致。修改参数后重新编译并下载。

| 所属文件 | 参数 | 当前值与单位 |
| --- | --- | --- |
| `Motion/pid.c` | `ROBOT_LEFT_KP / KI / KD` | 1.413 / 0.79 / 0.03 |
| `Motion/pid.c` | `ROBOT_RIGHT_KP / KI / KD` | 1.40 / 0.81 / 0.06 |
| `Motion/pid.c` | `ROBOT_INTEGRAL_LIMIT / ROBOT_I_SEPARATE` | 30 / 30；积分累加上限 / 误差门限 |
| `Motion/line_follow.c` | `ROBOT_BASE_SPEED` | 20 四倍频计数/10ms |
| `Motion/line_follow.c` | `states / speeds` | 九档线型与左右速度比例；40表示100%基础速度 |
| `Motion/line_follow.c` | `ROBOT_LINE_FALLBACK_RATIO` | 0.5；首次尚无有效线型时目标比例 |
| `Motion/controller.c` | `ROBOT_LINE_MIN_PWM` | 10%；运行时每轮正向PWM下限 |
| `Motion/controller.c` | `ROBOT_START_DELAY_MS / ROBOT_RUN_MS` | 2000 / 0 ms；0表示持续循迹 |
| `Motion/controller.c` | `ROBOT_TEST_ON_MS / OFF_MS` | 转2000ms、停2000ms |
| `Motion/controller.c` | `ROBOT_TEST_LEFT_PWM / RIGHT_PWM` | 30 / 30%；仅测试模式使用 |
| `Motion/controller.c` | `ROBOT_STALL_PWM / MS` | 35% / 500ms；无编码器反馈诊断门限 |
| `Motion/controller.c` | `ROBOT_MAIN_TIMEOUT_MS` | 250ms；主循环失去响应门限 |
| `Bsp/tb6612.c` | `ROBOT_*_MOTOR_SIGN` | 左右轮均+1；方向修正 |
| `Bsp/tb6612.c` | 四个 `ROBOT_TB6612_*_FORWARD_LEVEL` | AIN1/2=01、BIN1/2=01；正向电平 |
| `Bsp/tb6612.c` | `ROBOT_PWM_DEADBAND` | 5%；应小于循迹最低PWM |
| `Bsp/encoder.c` | `ROBOT_*_ENCODER_SIGN` | 左右轮均+1；物理前进应计正数 |
| `Bsp/board.c` | 三个 `ROBOT_*_ACTIVE_LEVEL` | LED、蜂鸣器、黑线DO均高有效 |
| `Bsp/i2c_bus.c` | `ROBOT_I2C_TIMEOUT_MS` | 5ms；单次等待超时 |
| `Devices/oled.c` | `ROBOT_OLED_ADDRESS` | 7位地址0x3C |
| `Devices/mpu6050.c` | `ROBOT_MPU_ADDRESS` 及滤波/标定参数 | 默认0x68；具体见IMU说明 |
| `Bsp/debug_uart.c` | `TX_CAPACITY` | 2048字节发送队列 |
| `empty.c` | `ROBOT_DISPLAY_MS / ROBOT_DEBUG_REPORT_MS` | 100 / 500ms；绘制/报告周期 |
| `empty.c` | 设备重试、启动/故障提示音、心跳亮灯时间 | 见顶部逐项中文单位说明 |
| `robot_config.h` | `ROBOT_MOTOR_TEST_MODE` | 0；1切换台架转停测试 |
| `robot_config.h` | 两项 `ROBOT_STOP_ON_*` | 均0；无效线型/编码器无反馈默认不锁存停车 |
| `robot_config.h` | `ROBOT_CONTROL_MS` | 固定10ms；现有PID按此周期整定 |

例如：只想调快直行，修改 `Motion/line_follow.c` 的 `ROBOT_BASE_SPEED`；只想调整转弯幅度，修改同文件的九档比例表；响应太慢或振荡时，再到 `Motion/pid.c` 调对应轮的系数。Ki/Kd 已包含离散周期，不要额外乘除 dt。

目标速度是编码器四倍频计数/10ms；PWM 是驱动占空比。最低10% PWM不等于实际机械转速为满速的10%。驱动死区、最小PWM、软件/硬件100%上限各自作用已在源码标明，修改时需保持相容。

## 本次保留的运行策略

初始化完成等待2秒，之后持续循迹。中线目标20/20，黑线向左偏降低左轮目标，向右偏降低右轮目标；各轮由自己的速度PID调节，正向PWM范围10%..100%。

五路全亮、全灭和其他无效组合均保持最近一次有效差速；启动后尚无有效线型时目标为10/10。重新识别标准线型后下一拍继续更新。

默认不因无效线型或编码器无反馈停车，不按100秒计时结束。启动等待、定时器配置错误、控制周期异常、主循环超时的停车行为保留。测试模式仍为固定PWM转2秒、停2秒。IMU离线不阻止循迹。

## 中文注释与扩展约定

每个模块头部有 `@file`、`@brief` 和职责说明；函数用 `@brief`、`@param`、`@retval`、`@note` 描述功能、输入输出、单位及调用限制，可在CCS悬停查看公共接口。参数定义与函数实现之间保留清楚的分区。

新增K230协议解析、云台指令等任务时，在 `empty.c` 主循环相应任务后接入；协议与算法仍分别放在自己的模块，参数放在该模块顶部。中断只读取已经校验的目标快照，避免在10ms控制中断中等待串口、I2C或运行耗时视觉计算。Type-C已占用UART0 PA10/PA11，后续K230接入需要重新分配或隔离接口。

引脚、PWM周期、定时器和UART波特率继续在SysConfig图形界面设置，详见 [SysConfig配置清单](SysConfig配置清单.md)。请勿手改生成文件。本次未改引脚与SysConfig。

其他细节见 [电机测试与串口诊断](电机循环测试与串口诊断.md)、[IMU角度与互补滤波](IMU角度与互补滤波.md)、[调试与扩展](调试与扩展.md)。
